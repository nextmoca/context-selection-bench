\begin{abstract}
Agentic language-model systems accumulate large intermediate state (conversation history,
tool metadata, retrieved documents, and prior results) that is often re-inserted into
prompts wholesale, raising cost and latency and enlarging the model's distraction surface.
Two families of remedies have emerged: \emph{selection}, which forwards a relevant subset of
state verbatim, and \emph{compression}, which rewrites or summarizes it. Published evaluations
are hard to compare: they use different base models, arms, and context lengths, frequently
score with the method authors' own scorer, and seldom report negative results, standardize
latency measurement, or close the reproducibility loop. We present a matched-protocol
benchmark \emph{program} for a context-selection layer, using one running system (\NP{}) as the
instrument under test. Under a single protocol (same base model, identity-gated items, one
arm per method, reference-metric scorers, and paired statistics), we make five
contributions. \textbf{(1)} On RULER, across five arms at two context lengths, the selection
layer scores above every tested configuration while the pure-compression arm scores below full
context; we report the full five-arm ordering and explicitly decline any categorical
``selection beats compression'' claim, because a compression-family arm outscored a
selection-family arm. \textbf{(2)} We report negative results as first-class findings: on an
agentic tool-use benchmark the layer falls $25$ percentage points below full history while
\emph{total} tokens rise; a summarization baseline does worse at higher cost; and
identical-configuration reruns flip outcomes on roughly $39\%$ of tasks, motivating validation
of agent reruns by byte-identity rather than statistical parity. \textbf{(3)} We describe a
composition-based operating-envelope gate keyed on a relevance gap and task-signature drift,
computed sub-millisecond in-process with no model calls, which stands down byte-identically where
selection does not pay ($208/208$ steps on the tool-use benchmark; $89\%$ engagement on RULER
with no statistically detectable aggregate difference from ungated selection); token-count gates
are insufficient because the winning and losing regimes occupy the same token scale.
\textbf{(4)} We treat reproducibility as a result: a public-harness (implementation-path)
replication reproduced the primary RULER finding (the selection layer beats full context at
both lengths under Holm-corrected per-length McNemar, pooled $+4.99\pp$, ${\sim}32\%$ fewer
tokens, lowest end-to-end cost) with the system reached only through a versioned hosted
adapter and no engine code in the harness. The extraction and rerun are ours, so the
independence established is of the code path, not the operator; a fully independent rerun, which
the released harness enables, remains open. We include a named commercial compression API at
parity (a small positive delta, not significant under the primary per-length test) and a
four-class latency-measurement methodology whose network decomposition is deliberately
constructed to favor the remote vendor. \textbf{(5)} We define an iso-quality selection-layer benchmark and sketch a
capacity-constrained extension with safe escalation as future work. Every number traces to a
results document and a checksummed artifact manifest; the harness, configurations, and seeds
are released with the paper.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Production agent systems are not single-turn chatbots. They maintain state across planning,
tool selection, retrieval, execution, review, and user interaction: the current request and
task parameters, prior messages and workflow history, agent and tool definitions, database rows
and retrieved documents, environment configuration, and prior tool results. The default
strategy in many systems is to insert most of this state into every model prompt. This appears
safe (the model has access to everything), but it raises token cost on every invocation,
increases latency as prompts grow, and enlarges the surface of irrelevant detail that can
distract generation; longer context does not guarantee higher fidelity.

Two families of remedies have emerged. A \emph{selection} layer forwards a relevant subset of
the accumulated state \emph{verbatim}, dropping the rest. A \emph{compression} layer instead
rewrites, summarizes, or shrinks the state so that more of it fits in fewer tokens. Both are
active areas of work, and both are typically reported by their authors on favorable surfaces.
The difficulty for a practitioner is that the published evaluations are not comparable to one
another: they use different base models, different competitor arms, and different context
lengths; they frequently score with a metric or judge chosen by the method's authors rather
than the benchmark's own published metric; they under-report negative results; they measure latency
in incommensurable ways (a local library call against a remote API call); and they rarely close
the reproducibility loop by releasing a harness an outsider can run to reproduce the headline.

This paper contributes a \emph{benchmark program} (not a single benchmark) for evaluating
a context-selection layer under a matched protocol. We use one running system, \NP{}
\citep{rao2026needlepath}, as the
instrument under test, but the object of the paper is the methodology and what it reveals, not a
product. Under one protocol (Section~\ref{sec:protocol}), fixing the same base model, items gated by
content hash and paired item-for-item, one arm per method run at its own operating point,
reference-metric scorers, and paired statistics, we make five contributions:

\begin{enumerate}
  \item A matched-protocol comparison across selection and compression methods on RULER, at two
  context lengths, with the full five-arm ordering and a deliberately narrow reading of it
  (Section~\ref{sec:ruler}).
  \item Negative results treated as first-class findings: an out-of-envelope regime where the
  selection layer loses and total tokens \emph{rise}; a compression arm whose \emph{billed}
  token count goes negative; and a run-to-run variance result that changes how agent reruns
  should be validated (Section~\ref{sec:negative}).
  \item A composition-based operating-envelope gate that decides when \emph{not} to act, why a
  token-count gate cannot do this, and the open contradiction between fail-open pass-through and
  a hard capacity cap (Section~\ref{sec:gate}).
  \item Reproducibility as a result: a public-harness (implementation-path) replication of the
  primary finding through a versioned hosted adapter (independence of the code path, not the
  operator), a named commercial-compressor arm at parity (not significant under the primary
  per-length test), and a latency measurement-class methodology (Section~\ref{sec:repro}).
  \item A definition of an iso-quality selection-layer benchmark and a capacity-constrained
  extension with safe escalation as future work (Section~\ref{sec:defn}).
\end{enumerate}

\paragraph{Scope and non-goals.} The instrument under test is a single system, described at the
architecture level of its prior public technical report (Section~\ref{sec:np}). We report on two
context lengths and make no scaling-law claim. Every arm is a distinct third-party method or a
baseline; we make no claim against a method we did not run under the matched protocol.

\section{Background and Related Work}
\label{sec:background}

\subsection{Selection versus compression}

We distinguish two families by what they emit. A \emph{selection} method chooses a subset of the
candidate state and forwards the chosen records unchanged; its risk is dropping a record that is
later needed. A \emph{compression} method transforms the state into a shorter form (by
rewriting tokens, summarizing spans, or wrapping verbose payloads behind a retrieval handle),
and its risk is that the transformation loses or distorts evidence. The distinction is about
the operation on kept content, not about the amount removed: a selection method that keeps a
record keeps it byte-for-byte.

\subsection{Methods evaluated}

Table~\ref{tab:arms} lists the arms. All are run under the matched protocol
(Section~\ref{sec:protocol}) at each method's own operating point; no arm is tuned to the
benchmark. LLMLingua-2 \citep{pan2024llmlingua2} rewrites the stack into a shorter, choppier
form. CPC \citep{liskavets2025cpc} selects verbatim at the sentence level via a $7$B GPU model.
ACON \citep{acon2025} replaces accumulated history with its own written summary as an agent
episode progresses. Headroom \citep{headroom} shrinks tool outputs and structured payloads while
keeping the originals behind a retrieval tool the model can call. Compresr \citep{compresr} is a
hosted commercial compression API. The baseline, \emph{full context}, forwards the entire stack
unedited.

We exclude three further classes of method, with reasons. LCLMs \citep{li2026lclm}, pretrained
encoder-decoder context compressors (a small trained encoder feeding a larger decoder), require a
custom-trained reader and are not drop-in. A second commercial compression API was evaluated and
excluded before any spend on the basis of its terms of service (a competitive-benchmarking
restriction, a naming/pre-approval requirement, and quote-only pricing that could not be
independently verified); that vendor is left deliberately unnamed throughout, no unverified pricing
is cited, and the vendor was not contacted. And we exclude the industrial context-engineering system
of \citet{lodha2026lcba} (\emph{Less Context, Better Agents}), because it is not externally
reproducible: evaluation requires a live proprietary enterprise environment and internal tooling, and
neither code, tools, nor data are publicly released (the paper's reproducibility appendix documents
internal replication only).

\subsection{Broader context}

The methods evaluated here sit within larger literatures that we survey briefly. \emph{Prompt
compression} spans token-level pruning and abstractive summarization of context. \emph{Retrieval and
reranking} select evidence by learned or lexical similarity rather than by a task signature.
\emph{Long-context evaluation} studies how models use (or fail to use) information placed deep
in a long prompt, the phenomenon RULER is built to probe. \emph{Agent-memory} systems manage what an
agent carries across the steps of an episode, the regime in which our out-of-envelope result
(Section~\ref{sec:appworld}) arises. This paper's contribution is a matched-protocol comparison
across representative methods from these families, not a taxonomy of them.

\subsection{The instrument under test}
\label{sec:np}

\NP{} is a context-selection layer whose method, \emph{selective state compression}, has been
described previously at the architecture level \citep{rao2026needlepath}.\footnote{The published
report \citep{rao2026needlepath} evaluated an earlier configuration on a
$100$-task live benchmark. Its headline figures (final-path input-token reduction $27.4\%$;
usefulness preserved or improved in $83\%$ of cases) come from a single base model scored by a
pairwise LLM judge rather than the benchmark's reference metric, and are not carried
forward here. Separately, that report's wrapper-suite figures are superseded by the
reference-metric, matched-protocol results reported in this paper.} It proceeds in five stages: it
builds a \emph{task signature} of the current request; it \emph{scores} each candidate state
record against that signature; it \emph{selects and formats} the chosen records; it applies a
\emph{risk-aware fallback} that fails open to the baseline prompt; and it exposes an
\emph{output-contract} layer. Throughout this paper the layer runs so that kept records are
emitted \emph{verbatim} (byte-for-byte); all token reduction comes from dropping whole records,
never from rewriting kept ones.

\section{Evaluation Protocol}
\label{sec:protocol}

\paragraph{Matched protocol.} Every comparison holds the following fixed. \emph{Same base model:}
one model (\texttt{gemini-3.1-pro-preview}) at temperature $0$ with identical decoding across
every arm, confirmed callable immediately before spend. \emph{Same items:} each arm sees the
same benchmark items, gated by SHA-256 content hashes and paired item-for-item. \emph{One arm,
one method:} each method runs at its own published or default operating point; no arm is tuned to
the benchmark. \emph{Reference-metric scorers:} accuracy is computed by each benchmark's own
published reference metric, reimplemented in the released harness and applied
identically to every arm on identical items; we never substitute a bespoke metric
of our own. Per-suite deviations from the official scoring artifacts, and why they
do not affect the within-run paired comparisons, are enumerated in
Appendix~\ref{app:scorers}. \emph{Paired statistics:} significance is assessed with McNemar's
test on paired binarized correctness \citep{mcnemar1947}, and confidence intervals with a paired
$10{,}000$-resample bootstrap (seed $42$) on the score delta.

\paragraph{Item pairing.} Some official exports contain legitimately repeated examples whose
index field is not unique within a task. We therefore pair items by row \emph{position} rather
than by index, and verify that every task/length cell carries the same number of rows with an
identical (index, position) sequence across arms, so that each comparison is genuinely paired
item-for-item (Appendix~\ref{app:stats}).

\paragraph{Latency measurement classes.} Latency figures are meaningless across placements unless
they are labeled. We stamp every latency figure with exactly one of the four measurement classes
below and never place figures of different classes in the same row without their labels:
\begin{itemize}
  \item \texttt{in\_process}: pure local compute on our hardware, no network;
  \item \texttt{hosted\_adapter\_localhost}: a request to a service we run on \texttt{127.0.0.1}
  (loopback, no wide-area network);
  \item \texttt{remote\_api\_e2e}: wall-clock round trip to a third-party API over the public
  internet, transport included;
  \item \texttt{remote\_api\_network\_adjusted}: \texttt{remote\_api\_e2e} minus the median
  TCP\,+\,TLS transport baseline to that host.
\end{itemize}
A fifth label, \texttt{vendor\_reported\_server}, marks a figure a third-party vendor reports from
its own server-side clock; it is a provenance tag for an externally-supplied number, not a
measurement class we control, and is never compared directly against our classes. This discipline
lets a reviewer verify that we did not let a local placement flatter one arm nor a remote placement
penalize another (Section~\ref{sec:latency}).

\paragraph{Provenance ladder and artifacts.} We rank evidence by how much of the pipeline an
outsider can reproduce: fully third-party data (strongest for data provenance); a third-party
generator instantiated with our seed; an in-repository reproducible harness; and, strongest for
\emph{reproducibility of the system under test}, an extracted public harness that reaches the
system only through a hosted adapter (Section~\ref{sec:repro}); the independence this establishes
is of the code path, not the operator. Every number in this
paper traces to a results document and a SHA-256 artifact manifest (Appendix~\ref{app:provenance});
per-item outputs live in object storage under those manifests, and the harness, pinned
configurations, and seeds are released with the paper.

\section{Matched-Protocol Comparison on RULER}
\label{sec:ruler}

\paragraph{Setup.} RULER \citep{hsieh2024ruler} generates long-context ``needle-in-a-haystack''
tasks over synthetic haystacks. We run $13$ tasks at each of two context lengths ($8$K and $16$K)
with $100$ items per task/length cell, using the official generator seeded by us and the official
scorer. One task, \texttt{niah\_single\_3}, is a dead-zero across all five arms ($0.0\%$ at both
lengths) due to a task-construction artifact (truncated answers) independent of method; we
exclude it from the headline $12$-task average and report the $13$-task average in
Appendix~\ref{app:ruler}.

\paragraph{Five-arm ordering.} Table~\ref{tab:ruler-scores} gives the $12$-task average score of
each arm. The ordering is the same at both lengths:
\[
\text{\NP{}} \;>\; \text{full context} \;>\; \text{Headroom} \;>\; \text{CPC} \;>\; \text{LLMLingua-2}.
\]
\NP{} is above every tested configuration at both lengths, and the pure-compression arm
(LLMLingua-2) is below full context at both lengths. We state this exactly and no more strongly.
In particular, we do \emph{not} claim that selection beats compression as a category: within the
same five-arm data, Headroom (a compression-family arm) outscored CPC (a selection-family arm) at
both lengths (Table~\ref{tab:ruler-pairwise}). The headline is about configurations, not families.

\section{Negative Results as First-Class Findings}
\label{sec:negative}

The credibility of a benchmark program rests on what it reports when the method loses. This
section reports three negative findings in full.

\subsection{An out-of-envelope regime: agentic tool use}
\label{sec:appworld}

We run AppWorld \citep{trivedi2024appworld}, an agentic tool-use benchmark with a third-party
environment, tasks, and official scorer, on a seeded $N{=}140$ subsample of the
\texttt{test\_normal} split with three arms: full history, \NP{}, and ACON (agentic
summarization). Results are in Table~\ref{tab:appworld}. \NP{} does \emph{not} preserve task
success: it scores $-25.0\pp$ below full history ($71.4$ vs.\ $96.4$; McNemar $p{=}2.28\times
10^{-8}$), and even though it cuts \emph{peak} context by $22.7\%$, the \emph{total} tokens spent
across the episode \emph{rise} by $12.3\%$, because trimming what fits in any single call
lengthens the trajectory. ACON loses harder ($-30.0\pp$) and pays a compression-model bill on top;
\NP{} beats ACON on economics (a significant $-\$0.0389$ per episode) but only directionally on
success ($+5.0\pp$, McNemar $p{=}0.19$, not significant). Neither method matches the uncompressed
baseline in this regime.

The cause is architectural, not a bug. \NP{} scores relevance against a task signature built from
the current step, which assumes a \emph{stable query}: true in retrieval and haystack regimes,
false in a ReAct loop where the information the agent will need is not predictable from the current
step. Two observations localize this. First, damage tracks engagement exactly: the $23$ of $140$
episodes where \NP{} never engaged succeeded $23/23$ ($100\%$), identical to baseline, and all $36$
discordant losses were engaged episodes. Second, failures came from dropping the \emph{wrong}
records, not too many (failed episodes dropped \emph{fewer} records than passed ones). The
fail-open guarantee did not help, because it is an engine-level guarantee that fires when
selection throws, not a relevance-level oracle: a selection that returns successfully while
dropping a later-needed record is indistinguishable from a perfect one. We therefore declare
AppWorld out of envelope for the selection thesis as configured, and do not cite it as evidence
for or against the approach on agentic tool use without a run designed to reach the pressure
regime first. Section~\ref{sec:gate} turns this diagnosis into scoped behavior.

\subsection{When a compression arm's billed tokens go negative}
\label{sec:headroom-negative}

Headroom's stated value proposition is ``$60$--$95\%$ fewer tokens, same answers'' by shrinking
payloads and keeping originals behind a retrieval tool. We report its token economics on a raw,
\emph{uncached} basis: a deployment with prompt caching would see a real marginal cost somewhere
between the content and billed bases below, so the negative billed figure is the correct number
absent a caching claim this run does not test, not an assertion that caching does not exist. On
RULER, and on that basis, the value proposition fails on two counts. \emph{Gross} reduction is
$25.3\%$ ($8$K) and $26.5\%$ ($16$K), nowhere near the advertised range, and only the two
pure-filler tasks reach it. More importantly, the retrieval round-trips add tokens back: on a
\emph{content} basis the net reduction is ${\sim}8.5\%$, and on a \emph{billed} basis (counting
the re-sent conversation on each retrieval round) the net is \emph{negative} ($-2.9\%$ at $8$K,
$-1.6\%$ at $16$K). The compressed-plus-retrieval round trip bills more total input than sending
the full prompt once, while accuracy is $-5.6/-2.6\pp$ below full context. The ``same answers''
claim does not hold on this surface.

\subsection{Run-to-run variance, and validating reruns by identity}
\label{sec:variance}

A probe of a proposed recovery mechanism surfaced a property of the agentic benchmark itself: on
AppWorld, identical-configuration reruns flip a task between pass and fail roughly $39\%$ of the
time. This has a methodological consequence that we adopt throughout: an agentic rerun cannot be
validated by comparing success rates across reruns, because that comparison is confounded by
variance and unfalsifiable at affordable $N$. Where we need to prove that a change is safe, we
prove it by \emph{byte-identity} (that what the agent receives is character-for-character what
it would have received otherwise), which is a structural property that holds regardless of the
model's run-to-run nondeterminism. Section~\ref{sec:gate} uses exactly this: the operating-envelope
gate is validated by showing its stand-down is byte-identical to full history, not by rerunning and
comparing dice rolls.

\section{A Composition-Based Operating-Envelope Gate}
\label{sec:gate}

The AppWorld result (Section~\ref{sec:appworld}) is not that selection is wrong but that it has an
operating envelope: it pays where the context is junk-heavy and hurts where every record may be
needed and the query moves each step. A production layer therefore needs to decide \emph{when not
to act}. We describe such a gate at the architecture level of the system's technical report
\citep{rao2026needlepath}.

\paragraph{Why a token-count gate cannot do it.} The winning regime (RULER) and the losing regime
(AppWorld) occupy the \emph{same} absolute token scale, roughly $8$--$16$K. Any threshold on
token count that engages on RULER therefore also engages on AppWorld, and vice versa. Separating
the regimes requires a signal about the \emph{composition} of the context, not its size.

\paragraph{The two signals.} The gate keys on two composition signals, each computed from
statistics the selector already produces, with zero model calls and no network in the selector
call graph: a \emph{relevance gap} (the shape and separation of the relevance-score
distribution over candidate records) and \emph{task-signature drift} (the step-to-step
change in the task signature). In a haystack regime, a few records score far above a flat tail (a
large gap) and the query is stable (low drift), and the gate engages; in a ReAct regime, scores
are flatter and the signature moves each step, and the gate stands down. The gate adds
${\sim}0.83$\,ms per step in steady state ($1.93$\,ms including cold start), in the
\texttt{in\_process} class.

\paragraph{Stand-down is byte-identical.} When the gate stands down, the agent receives full
history \emph{byte-for-byte}, through a shared fallback code path; this is a structural guarantee,
not a statistical one, so ``stand-down cannot hurt'' is a logical consequence rather than a
measured claim. On an AppWorld gate-behavior run with the gate acting, all $208$ of $208$ optimizer
steps stood down ($100\%$), byte-identically. On RULER, the gate engages on $89.0\%$ of items
($90.5\%$ at $8$K, $87.6\%$ at $16$K), and the gate-vs-selection score delta shows no statistically
detectable aggregate difference: its $95\%$ CI straddles zero at both lengths and overall
($+0.0021$ overall, CI $[-0.0014,+0.0059]$), with $156/156$ live selections identical to the
reference (Table~\ref{tab:gate}). We disclose one regressing cell:
\texttt{niah\_multivalue} at $16$K genuinely loses $-0.0775$ (CI $[-0.100,-0.055]$) where the
ungated arm was winning; it washes out in the aggregate but is a real cost of conservative
calibration, reported rather than buried. In production the gate's default is a shadow mode that
computes and logs its decision without changing behavior: a configuration flip, not new
plumbing. This run measures gate \emph{behavior} (stand-down rate, signals, and the
byte-identity of the stand-down), not post-gate task success: we deliberately did not re-estimate
task success after gating, because the run-to-run variance of Section~\ref{sec:variance}
(${\sim}39\%$ task flips) makes that measurement uninformative, and the byte-identity argument
replaces it. We also state the cost plainly: in the stand-down regime the layer provides zero token
reduction: it is a fixed-cost pass-through, and that is the designed behavior.

\paragraph{Discussion: the capacity-cap contradiction.} Fail-open pass-through presumes that full
context \emph{fits} the downstream call. Under a hard capacity cap it does not, and standing down
to full context is not an available behavior. The layer today has exactly two behaviors (select
and stand down), and this regime needs a third, \emph{escalate}: a declaration that no safe
subset fits the budget. Escalation must be \emph{additive}, never a cap on the load-bearing
pass-through path that underwrites the byte-identity guarantee. It is currently a roadmap item,
planned and not currently available; we return to it as future work (Section~\ref{sec:defn}) and
cite it as the reason the present gate is a two-behavior device.

\section{Reproducibility as a Result, and Latency Measurement Classes}
\label{sec:repro}

\subsection{Replication through an extracted public harness}
\label{sec:replication}

The strongest thing a benchmark can say about a \emph{system} is that its result survives new
machinery. We extracted the RULER harness into a standalone public repository (\texttt{csbench})
and re-ran a three-arm RULER surface it had never seen, with \NP{} reached \emph{only} over HTTP
through a hosted adapter (\wire{}, versioned operating point \oppoint{}). No engine code runs in
the public harness; it sees only a neutral request/response wire contract. This is simultaneously a
benchmark result and an end-to-end validation that the extraction preserves matched-protocol
fidelity.

We call this a \emph{public-harness}, or \emph{implementation-path}, replication, and are precise
about its scope. The extraction and the rerun were both performed by us; the independence it
establishes is of the code path (no engine code runs in the harness, and the system is reached
only through the versioned adapter), not of the operator. A fully independent replication by an
unaffiliated party remains future work; we release the harness and the adapter's wire contract
precisely so that anyone can perform it, and we invite exactly that.

By the program's primary test (two co-primary per-length McNemar tests on paired binarized
correctness, Holm-corrected at family $\alpha{=}0.05$), \NP{} beats full context at both lengths
($+4.64\pp$, $p{=}0.014$ at $8$K; $+5.33\pp$, $p{=}0.003$ at $16$K; both significant after Holm).
We do not claim preregistration: McNemar on binarized correctness has been the program's standing
primary test since the RULER protocol was fixed (2026-07-07, before this run), and binarizing at
the reference threshold (RULER score $\ge 1.0$) mirrors the benchmark's own reference metric. As secondary,
descriptive statistics, the pooled McNemar is $p{=}0.0001$ and the paired-bootstrap $95\%$ CI on
the pooled accuracy delta is $+4.99\pp$ $[+3.66,+6.32]$; our stated sensitivity analysis (a
paired bootstrap on the continuous, unbinarized scores) gives $+2.50\pp$ $[+1.27,+3.73]$, the
same direction. \NP{} cuts average input tokens ${\sim}32\%$ ($11{,}784 \to 7{,}977$ per item);
this holds \emph{despite} a $40\%$ fallback rate, since fallback items save zero tokens and are
scored identically to full context, so the lift comes entirely from the engaged selections. \NP{}
is also the cheapest arm end-to-end (Table~\ref{tab:replication}), and its selection latency over
the adapter is reported in Section~\ref{sec:latency}. The result lands inside the original
$+5.8/+4.7\pp$ band from Section~\ref{sec:ruler}: the primary finding survives a fresh day, a new
harness, and the customer-facing HTTP path.

\subsection{A commercial-compressor arm, read honestly}
\label{sec:compresr}

The same run included Compresr, a hosted commercial compression API, at its default operating point
with no tuning. Its result is parity to slightly positive, and not statistically significant under
the program's primary test. We are explicit about the test hierarchy, because the two statistics
can diverge and a reader must not think the test was chosen after seeing the answer. The primary
test is the standing program convention (two co-primary per-length McNemar tests on paired
binarized correctness, Holm-corrected), and Compresr clears it at neither length ($8$K
$p{=}0.101$, $16$K $p{=}0.871$; pooled $p{=}0.193$, secondary). Descriptively, its pooled accuracy
delta is $+1.45\pp$ with a bootstrap CI $[+0.09,+2.82]$ that marginally excludes zero; the
continuous-score sensitivity analysis gives $+0.88\pp$ $[-0.38,+2.12]$, straddling zero. We
therefore characterize the arm as parity to slightly positive, not statistically significant under
the primary test, at ${\sim}22\%$ fewer tokens, the best showing of any compression-family arm
in the program, and still without a statistically supported lift. \NP{} is the only arm that
improves accuracy and reduces tokens with support from the primary test; no arm ties \NP{}. We
never cite the Compresr figure beside the vendor's marketing without this label. Compresr is
excluded from any headline speed claim, for the reasons in Section~\ref{sec:latency}.

\subsection{Latency, decomposed into measurement classes}
\label{sec:latency}

Placing an in-process local method next to a remote API in an unlabeled latency table would be
meaningless or misleading. We therefore decompose Compresr's latency using the four classes of
Section~\ref{sec:protocol} and a network model built to \emph{favor the vendor}, so the
decomposition cannot be accused of inflating a remote competitor's latency
(Table~\ref{tab:latency}). We measure, in the \texttt{remote\_api\_e2e} class, a cold TCP\,+\,TLS
transport baseline (median $23.1$\,ms over $50$ cold sockets) and a warmed service floor (median
$98.8$\,ms), whose \texttt{remote\_api\_network\_adjusted} value is $75.6$\,ms (each network
adjustment is computed on unrounded medians, so displayed differences may round to within $0.1$\,ms).
On the RULER run, Compresr's end-to-end median is $252/431$\,ms ($8$K/$16$K); subtracting the full
transport baseline gives a network-adjusted $229/408$\,ms; the vendor's own server clock reports
$121/255$\,ms.

The adjustment is deliberately vendor-favoring. Because it subtracts the \emph{full} cold handshake
from \emph{every} item (more transport than a keep-alive'd client actually pays per item), it
attributes \emph{less} latency to the service than is really there, and it still leaves payload
transfer inside the figure. It is thus a \emph{lower} bound on the service-side-plus-payload time,
not an upper bound: over-subtracting the handshake can only shrink the figure and flatter the
vendor. That this lower bound still lands \emph{above} the vendor's own server clock ($229$ vs.\
$121$\,ms at $8$K, $408$ vs.\ $255$\,ms at $16$K) is consistent with it containing payload transfer
the vendor's internal timer excludes.

\NP{}'s own path in this run is \texttt{hosted\_adapter\_localhost}: the median per-item adapter
round trip (in-process selection plus loopback transport) is $52.2$\,ms at $8$K and $77.1$\,ms at
$16$K, with a well-behaved distribution and no multi-second retry tail. The adapter's server-side
selection timer alone (\texttt{in\_process}) is $9.6$/$10.9$\,ms, consistent with the
$8.5$--$14.5$\,ms measured directly on the RULER run (Section~\ref{sec:ruler}); the remainder is
loopback transport, not compute. All per-item figures
are medians, because rate-limit backoff at free-tier concurrency (the arm ran at $\le 2$ in-flight
requests) injects multi-second retry sleeps into a minority of items ($146/1300$ at $8$K,
$172/1300$ at $16$K; $p90 \approx 60$\,s, the retry interval); the median is robust to these, the
mean and $p90$ are not. Compresr is excluded from any headline speed claim regardless.

\section{Defining an Iso-Quality Selection-Layer Benchmark}
\label{sec:defn}

\subsection{Iso-quality selection}

The program above suggests a definition. An \emph{iso-quality selection-layer benchmark} holds
answer quality fixed (via a reference-metric scorer, matched arms, and paired statistics) and
measures token, latency, and cost economics at equal-or-better quality, with \emph{engage-versus-
stand-down} as a first-class axis rather than an implementation detail. The clean-desk controls in
this program show why the stand-down axis matters: on GSM8K \citep{cobbe2021gsm8k}, a single tidy
page with nothing to remove, the layer is neutral ($+0.18\pp$, CI spanning zero)\footnote{The GSM8K
figure comes from a separate full-set run over all $1319$ test items, not from the public
\fn{controls\_v1} harness; per-budget \NP{}-minus-full exact-match deltas range from $-0.15$ to
$+0.38\pp$. It is deposited hash-only (aggregate plus SHA-256 manifest) and is regenerable with the
released harness.}; on TruthfulQA
\citep{lin2022truthfulqa} it is a byte-identical no-op ($0.78$ on all three arms, $0$ flipped
answers, McNemar $p{=}1.0$, $100\%$ stand-down). ``Do nothing, correctly'' is a required, testable
behavior, and a benchmark that only rewards trimming would miss it. Document-QA and tool-calling
controls (SQuAD~v2 \citep{rajpurkar2018squad2}, BFCL \citep{bfcl2024}) similarly test that needed
evidence and rigid schemas survive selection. On a reproducible re-run there is no statistically
detectable difference from full context: BFCL accuracy $-1\pp$ (McNemar $p{=}1.0$) and SQuAD~v2
$\Delta$F1 between $-0.0075$ and $-0.0112$ (paired-bootstrap CIs straddling zero). These are
within-run observations that the needed evidence and schemas survive selection, not claims about
absolute quality; the gate stood down on all items in these controls, so they show no detectable
regression rather than repair under stress.

\subsection{A capacity-constrained extension with safe escalation (future work)}

The capacity-cap contradiction of Section~\ref{sec:gate} defines the natural next benchmark, which
we sketch here as a design and do not run or claim. In a \emph{capacity-constrained evidence
selection} task, the full context does not fit the budget, so standing down is unavailable and a
correct system must sometimes \emph{escalate} rather than answer. Two budget contracts follow: a
soft budget, where overflow is permitted and its cost measured, and a hard budget, where
non-reducible cases must escalate and a silent truncation or a confident-but-insufficient answer is
a failure. Cases fall in three classes (reducible, boundary, and non-reducible), and the third
is what makes it a real test, because no subset within budget suffices. The metrics are a
safety-first sequence with no composite score: the headline is the highest safe completion rate
subject to a preregistered ceiling on catastrophic misses, and because a system that escalates
everything is trivially safe but useless, escalation rate is always reported beside safety. We use
the language ``capacity-constrained evidence selection with safe escalation'' and never ``provably
safe selection'': answerability checking is measured risk control, not a formal guarantee over the
input distribution. A feasibility triage over a public regulatory-filing corpus finds the build
tractable, with dataset contamination as the primary kill risk and mitigations (closed-book
controls, post-cutoff filings, held-out generators) designed in. Escalation as a product behavior
is planned and not currently available.

\section{Limitations}
\label{sec:limitations}

We state the limitations plainly.
\begin{itemize}
  \item \textbf{Vendor authorship.} This evaluation was designed, run, and written by the authors,
  who develop the instrument under test (see the conflict-of-interest statement). The mitigations are
  reference-metric scorers applied identically to every arm (Appendix~\ref{app:scorers}), a released harness and manifests, first-class negative results, and the
  public-harness replication of Section~\ref{sec:replication}, which is implementation-path, not
  operator-independent.
  \item \textbf{Proprietary instrument.} The selection layer and its operating-envelope gate are a
  proprietary system, described here at the architecture level of its technical report
  \citep{rao2026needlepath}; the released artifact is the
  evaluation harness, not the system, so we claim artifact and code-path reproducibility, not
  independent-system reproducibility.
  \item \textbf{Operating-point confound.} Each arm is run at a single published or default
  operating point, so method quality and compression aggressiveness cannot be separated; all
  orderings are configuration-scoped. A matched-budget or Pareto comparison across operating points
  is future work.
  \item \textbf{Single model family per run.} Every arm within a run uses one base model
  (\fn{gemini-3.1-pro-preview} or \fn{gpt-4o-mini}, per run); we make no cross-model
  generalization claim.
  \item \textbf{Deterministic decoding.} All runs use temperature $0$; deterministic decoding may
  interact differently with rewritten or reordered prompts than sampling would, and we do not
  characterize that interaction.
  \item \textbf{Single seed and run-day.} Each headline result is one seed on one run-day; the
  ${\sim}39\%$ agentic task-flip rate (Section~\ref{sec:variance}) is why we validate the gate by
  byte-identity rather than rerun parity, but the non-agentic results are likewise single-seed.
  \item \textbf{Synthetic-data dominance of RULER.} The headline comparison rests on RULER, whose
  haystacks are synthetically generated; strong RULER behavior need not transfer to natural
  long-context distributions.
  \item \textbf{Latency class stated per figure.} The $8.5$--$14.5$\,ms selection latency is
  \texttt{in\_process}; the replication adapter round trip is \texttt{hosted\_adapter\_localhost}
  ($52.2$/$77.1$\,ms); a hosted production deployment adds wide-area transit and is measured in the
  \texttt{remote\_api\_*} classes.
  \item \textbf{Fallback rate.} The replication run has a $40\%$ fallback rate; those items save no
  tokens and score as full context, so the reported lift is entirely from engaged selections.
  \item \textbf{Document-QA and tool-calling controls.} On a reproducible re-run, SQuAD~v2 and BFCL
  show no statistically detectable difference from full context (Section~\ref{sec:defn}); these are
  within-run observations about evidence and schema survival, not claims about absolute quality, and
  the gate stood down on all items, so they show no detectable regression rather than repair under
  stress.
  \item \textbf{Excluded artifact task.} \texttt{niah\_single\_3} is a dead-zero across all arms
  (truncated reference answers) and is excluded from the headline $12$-task average; including it
  changes the \NP{}-vs-full deltas by $\le 0.5\pp$ and leaves the ordering unchanged
  (Appendix~\ref{app:ruler}).
  \item \textbf{RULER item pairing.} The official export contains legitimately repeated examples
  whose index is not unique within a task; all comparisons are paired by row position, verified to
  $100$ rows per cell with an identical (index, position) sequence across arms.
  \item \textbf{Two context lengths only.} We report $8$K and $16$K and make no scaling-law claim.
  \item \textbf{Compresr at free-tier concurrency, and API drift.} The commercial arm was run at
  $\le 2$ in-flight requests, where rate-limit backoff contaminates the mean (we report medians);
  and, like any hosted third-party service, its API may drift in version or behavior after our run
  date, so its numbers are pinned to the recorded package version and run date.
  \item \textbf{Gate calibration.} The operating-envelope gate's calibration is a conservative
  starting operating point fit on the offline signal set with no held-out split; it is not a
  generalization claim to unseen tasks.
\end{itemize}

\section{Conclusion}
\label{sec:conclusion}

The honest picture of a context-selection layer is regime-dependent. It wins where the context is
junk-heavy (RULER: above every tested configuration at both lengths, with the pure-compression arm
below full context), stands aside byte-identically where trimming would not pay (agentic tool use),
and needs a third behavior, escalation, where the context does not fit at all. The negative results
(an out-of-envelope loss with total tokens rising, a compression arm's billed tokens going negative,
and $39\%$ run-to-run task-flip that forces validation by identity rather than parity) are not
footnotes to the wins but the spine that makes the wins credible. Reproducibility is
advanced by a public-harness (implementation-path) replication of the primary finding through the
same hosted adapter a customer would use; a fully operator-independent replication, which the
released harness makes possible, remains open. The transferable contribution is the methodology: a
matched protocol, negative
results reported as first-class, latency measured in labeled classes, and the operating envelope
treated as an evaluation axis rather than an afterthought.

\section{Scorer Provenance}
\label{app:scorers}

Every accuracy figure in this paper is produced by a single per-suite scorer that is fixed before
the comparison and applied identically to every arm on identical, position-paired items. For the
five public suites bundled in the released harness (RULER, SQuAD~v2, BFCL, TruthfulQA, and GSM8K),
that scorer is a reimplementation of the benchmark's published reference metric, not a call into
the benchmark's original scoring package; only the datasets are obtained from their official
sources. AppWorld is the exception: its numbers come from AppWorld's own official evaluator running
in the third-party environment. Table~\ref{tab:scorers} maps each suite to its official scoring
artifact, what the harness implements, and the principal deviations; the paragraphs below add, per
suite, why the within-run paired claims survive each deviation.

\paragraph{Why common-mode scorer choices do not distort a paired comparison.} Every claim in this
paper is relative and within-run: a delta between two arms scored by the same function on the same
items, never an absolute score submitted to a leaderboard. A scorer that reimplements a reference
metric can differ from the official artifact in absolute level, but because it scores all arms
identically, that difference is common-mode and cancels in the arm-versus-arm delta and in the
paired McNemar and bootstrap tests, which read only per-item agreements and disagreements. On the
clean-desk controls (SQuAD~v2, BFCL, TruthfulQA, GSM8K) the operating-envelope gate additionally
stood down on all or nearly all items, so the selection arm received inputs byte-identical to the
full-context arm and no scorer could separate them even in principle; those controls therefore
report the absence of a detectable regression, not an absolute quality ranking.

\paragraph{RULER.} The harness scores a reimplemented substring string-match (recall) over the
official RULER-generated JSONL: \texttt{string\_match\_part} for \texttt{qa\_*} tasks and
\texttt{string\_match\_all} (fractional recall over all needles) otherwise, following RULER's
convention. The arms are run through this harness rather than NVIDIA's evaluation harness and are
not an official RULER leaderboard submission, as the released \texttt{matrix.json} records. The
primary test binarizes each arm at RULER's own all-needles threshold (score $\ge 1.0$) and compares
arms pairwise on identical haystacks, so the reimplemented matcher is applied identically to every
arm.

\paragraph{SQuAD~v2.} The harness loads the official \texttt{rajpurkar/squad\_v2} validation split
and scores with SQuAD-style normalized EM/F1. Three deviations from \texttt{evaluate-v2.0} matter:
it is a reimplementation, not the official script; unanswerable examples are filtered at load, so
SQuAD~v2's no-answer scoring is not exercised; and the reported figure is an answer-preservation
agreement between the full-context and reduced-context answers, with the gold answer used only as a
secondary containment check, rather than EM/F1 against gold. The paper's SQuAD claim is exactly the
within-run observation that needed evidence survives selection ($\Delta$F1 confidence intervals
straddling zero), not an absolute SQuAD~v2 score, and the gate stood down on every control item.

\paragraph{BFCL.} This is the largest deviation. The harness scores the \texttt{simple} category of
\texttt{BFCL\_v3} with a deterministic argument-value-recall proxy (a call counts as matched when at
least half of the expected parameter values appear in the response), optionally augmented by an LLM
judge ($\ge 3/5$); it does not run the official AST or executable-function checker. The same proxy
is applied to every arm, and the gate stood down on all BFCL control items, so the full-context and
selection arms received near-identical prompts; the paper's claim is only that rigid tool schemas
survive selection with no detectable difference (McNemar $p{=}1.0$), which does not depend on the
proxy's absolute calibration. Because this scorer is a simplified proxy rather than BFCL's reference
metric, no absolute BFCL accuracy is claimed.

\paragraph{TruthfulQA.} The harness uses the official \texttt{multiple\_choice} MC1 targets (pinned
dataset revision) but scores generative single-letter selection accuracy: the model emits a choice
letter that is compared to the single correct option, rather than the official log-probability MC1
metric, and MC2 is not implemented. The paper's TruthfulQA result is a byte-identical no-op ($0.78$
on all three arms, zero flipped answers, $100\%$ stand-down), so with identical inputs across arms
the metric definition cannot change the paired result.

\paragraph{GSM8K.} GSM8K has no single canonical scorer package; the community convention is exact
match on the final numeric answer using the \texttt{\#\#\#\#} gold marker. The harness reimplements
that convention (prefer the \texttt{\#\#\#\#} marker, else the last number, float-tolerant
comparison). GSM8K is used only as a diagnostic clean-desk control, and its reported figure is
neutral ($+0.18\pp$, confidence interval spanning zero) with the same scorer applied to every arm.

\paragraph{AppWorld: the genuine official evaluator.} AppWorld's Task Goal Completion numbers
(Section~\ref{sec:appworld}) are produced by AppWorld's own official evaluator running against the
third-party AppWorld environment, not by any scorer of ours, and its in-run reward signal is not
used as ground truth. AppWorld is therefore the one suite in this paper whose accuracy is measured
by the benchmark's genuine official scorer, and it is reported as a negative result.

\section{Reproducibility Details}
\label{app:repro}

The replication (Section~\ref{sec:replication}) ran entirely on the extracted public harness
(\texttt{csbench}, released with this paper), with \NP{} reached only over HTTP through the hosted
adapter at the versioned, immutable operating point \oppoint{} recorded in every per-item row. The
harness sees only a neutral request/response wire contract at \wire{}; no engine code runs in it.
The base model is \texttt{gemini-3.1-pro-preview} at temperature $0$ with a fixed output-token cap,
identical across arms. Per-item artifacts (per arm, per task/length cell) are stored in object
storage with a SHA-256 manifest. Latency measurement uses the committed \texttt{csbench.latency}
utilities; the transport baseline and service floor were measured on the same date as the run.

\section{Statistical Methods}
\label{app:stats}

\paragraph{Primary test and decision rule.} The program's primary test for a two-arm comparison is a
pair of \emph{co-primary} per-length McNemar tests on paired binarized correctness
\citep{mcnemar1947}, Holm-corrected within the two-test family at $\alpha{=}0.05$; both per-length
results are always reported. This convention was fixed when the RULER protocol was established
(2026-07-07), before the runs reported here, so we describe it as a standing convention and do
\emph{not} claim formal preregistration. McNemar uses the $\chi^2$ form with continuity correction
when the discordant count is large and the exact binomial form otherwise. Correctness is binarized
at the benchmark's own threshold (for RULER, score $\ge 1.0$); binarizing at that
threshold keeps the primary test faithful to the benchmark's own reference metric.

\paragraph{Secondary and sensitivity statistics.} Pooled McNemar and paired-bootstrap confidence
intervals ($10{,}000$ resamples, seed $42$) on the accuracy (mean fractional score) delta are
reported as secondary, descriptive statistics. A paired bootstrap on the \emph{continuous}
(unbinarized) scores is the stated sensitivity analysis, reported alongside the binarized primary
result wherever the two could diverge (Sections~\ref{sec:replication}, \ref{sec:compresr}).
Cell-level McNemar tallies (Section~\ref{sec:ruler}) are exploratory and uncorrected for
multiplicity; the confirmatory aggregate test for the headline comparison is the pooled replication
McNemar.

\paragraph{Pairing.} Items are paired by row position, not by a non-unique index field, with a
per-position alignment assertion; every task/length cell is verified to contain the same number of
rows with an identical (index, position) sequence across arms.
